# editor-syntax-fixture-ini

A test fixture: a small INI grammar of our own, built as a native grammar
library (a shared library exporting `tree_sitter_ini`), the shape of a
grammar the editor loads at run time. The crate docs (`src/lib.rs`) say who
uses it and why it is a build-script product rather than a Cargo `cdylib`.
The editor never links it (`deny.toml`).

## Files

- `grammar/grammar.js`: the grammar, ours (GPL-3.0-or-later, as the
  workspace). Its node kinds and fields are fixed, since the adapter's corpus
  and the queries name them: `document`, `section` (field `name`),
  `section_name`, `pair` (fields `key` and `value`), `key`, `value` and
  `comment`.
- `grammar/src/`: `parser.c`, `tree_sitter/{parser,alloc,array}.h`,
  `grammar.json` and `node-types.json`, generated by the tree-sitter CLI,
  checked in and **never edited**. `mise run c-fmt` and `mise run c-format`
  leave this directory out (`docs/dev-practices/the-gate.md`, "Formatting").
- `grammar/exports.c`: the fixture's own exports beside the grammar's,
  clang-formatted and checked like the rest of the repository's C.
- `grammar/queries/highlights.scm`: the highlights query that sits beside
  the library, which the syntax contract draws with
  (`editor_syntax::contract::Corpus::highlights`).
- `build.rs`: compiles `grammar/src/parser.c` and `grammar/exports.c` with
  the C compiler `cc` finds, and links them as `OUT_DIR/libtree-sitter-ini.dylib`
  (macOS) or `OUT_DIR/libtree-sitter-ini.so` (elsewhere). It also copies
  `grammar/queries/highlights.scm` to `OUT_DIR/queries/highlights.scm`, so
  the library's directory has the layout a grammar declaration's default
  query directory reads (`<library dir>/queries/`).
- `src/main.rs`: prints the built library's path, for `mise run ffi-test` to
  hand to Lean's `contract-test`.

## Generating the parser

`grammar/src/` was generated on 2026-11-26 by **tree-sitter CLI 0.27.2**, the
release of the pinned library (`tree-sitter = "=0.27.2"` in
`crates/editor-syntax-treesitter/Cargo.toml`). It writes ABI 15
(`LANGUAGE_VERSION` in `parser.c`), inside the library's
`MIN_COMPATIBLE_LANGUAGE_VERSION..=LANGUAGE_VERSION`. The CLI was installed
with `mise install tree-sitter@0.27.2`. After a change to `grammar.js`,
generate it again with that version:

```sh
cd crates/editor-syntax-fixture-ini/grammar && tree-sitter generate
```

and commit `grammar.js` and `grammar/src/` together.

## The exports

Each export is a fixture for one property of the registration contract
(`editor_syntax::contract::registration`), not a grammar to use:

- `tree_sitter_ini`: the generated grammar, named `ini`, which is not one of
  the grammars compiled into the adapter. It is registered and held to the
  syntax contract and the registration contract's `REGISTERS`.
- `tree_sitter_json`: the same grammar under the name of a compiled-in
  grammar, `json`, in `exports.c`: a library that overrides it (`OVERRIDES`).
  The compiled-in `json` ships a highlights query and is reparsed
  incrementally; once overridden from a source declaring no policy, the
  name ships no query and is reparsed whole.
- `tree_sitter_abi_0`: a language whose ABI version is 0 and every other
  field zero, in `exports.c`. ABI 0 is below any version the parsing library
  will accept, so it stays refused through library bumps
  (`UNSUPPORTED_ABI`); the adapter reads only that field and refuses it
  before any parser is made.

## Who reuses it

The roadmap `syntax-runtime-grammars` reuses the fixture in its later phases:
a language naming a grammar file (phase 4) and a new language highlighted in
the editor, and a run-time grammar taking a compiled-in one's place (phase 5).
